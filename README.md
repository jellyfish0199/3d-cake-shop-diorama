# cake-shop-diorama

把「Wonder Half Sugar Dreamland · 四季甜点铺」这类 Three.js 甜品店立体模型游戏**从零复刻或持续迭代**的技能。

## 技能名称

`cake-shop-diorama`

## 使用方法

**触发**：只在用户要求**做一个甜品店立体模型游戏**（或要求复刻/重建这座甜品店本身）时激活；显式调用 `/cake-shop-diorama` 也可。单独提到四季、昼夜、水母加载页、出生点、面板等关键词时**不触发**——只有当这些要求是针对这座甜品店游戏、且本技能已被激活时，才作为后续迭代指令使用。

**修改现有项目的流程**（AI 自动执行）：
1. 在模块地图里定位改动点（shop/props/pixel-world/navigation/season/ui/music/main 各管一摊）
2. 只改用户点名的文件——范围规则是硬性的
3. `node --input-type=module --check` 语法检查 → `node build-static.mjs` 构建
4. 本地静态服务 + 无头 Chrome 在 1280×900 / 390×844 / 844×390 三种窗口截图验证
5. 发布后必须到公共域复核：零报错、零资源加载失败才算完成

**从零复刻**：读取 `references/prompt-recipe.md` 里的 master prompt，含全部权威数值（建筑尺寸、碰撞圈、出生点、相机位、日月锚点）。

## 用途

- 一句话复刻整座甜品店（建模、四季、昼夜、点单玩法、音乐、加载页全带）
- 针对本游戏的局部迭代：改出生点、调日月行为、挪 UI 面板、换加载页贴图、修手机端视口 bug
- 避免重复踩坑：CDN 同名缓存、几何体合并崩溃、屏幕追随式日月、移动端整页上移等已有成熟解法

## 注意事项

1. **触发边界**：不做泛用 Three.js/网页技能；非"建甜品店游戏"的请求不要套用本技能
2. **范围铁律**：只改用户明确要求的东西；看起来需要顺手改的，先说明并等确认
3. **日月是固定世界锚** `(-14, 9, -12)`：不要改回"屏幕位置追随视角"——那会导致太阳压店名、俯视时月亮掉下来的旧 bug；极端俯视时日月自然离开画面是预期行为
4. **出生点两处同步**：初始位置在 `pixel-world.js`，打包完成后的归位在 `main.js`，改一处必须改另一处
5. **构建产物不可手改**：`dist/` 是生成物，改 `src/` 后重新构建
6. **公共链接按版本发**：CDN 按路径缓存且忽略 `?v=`，每次更新必须用新的版本化目录（见 `references/deploy-cdn.md`）
7. **不虚报测试**：只报告真实跑过的浏览器/设备结果
